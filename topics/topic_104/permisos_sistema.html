Permisos y propiedad de recursos den GNU/Linux

Modo de un fichero

Los sistemas GNU/Linux trabajan con lo que se conoce como el modo de un fichero. Este concepto engloba el conjunto de directivas de seguridad que aplicamos a todos los usuarios del sistema en función de los diferentes bits de permiso . Para realizar esta gestión de permisos el sistema agrupa a los usuarios del sistema en 3 entidades , por lo que cada vez que se intenta acceder a un recurso en el sistema se evalúa la entidad a la que pertenece ese usuario.

La combinación de los 3 bits de permiso que existen para cada una de las entidades conforma los 9 permisos aplicables a un recurso que se conocen como el modo de un fichero, y el comando chmod es la herramienta que nos va a permitir administrarlos.

Entidades

Los sistemas GNU/Linux trabajan con el concepto de entidad , que no es más que un método para diferenciar a los usuarios del sistema y así poder aplicarles configuraciones de permiso distintas.

Las 3 entidades con las que trabajan los sistemas GNU/Linux son:

  • owner: es el propietario del recurso. Tendrá una configuración de permisos exclusiva para él y también es quien puede modificar el modo del fichero (sus permisos)
  • group owner: es el grupo propietario del recurso. Consiste en un grupo del sistema al que podemos aplicar una configuración de permisos concreta, ya sea la misma que al propietario ( owner ) o bien otra distinta, pero que queremos aplicarla a un conjunto de usuarios del sistema
  • others: engloba a todos los usuarios que no se encuentran en las 2 entidades anteriores, a los que aplicamos otra configuración de permisos.

Es importante entender que un usuario puede gestionarse con una entidad diferente en cada recurso del sistema. Es posible que sobre un recurso seamos owner , sobre otro formemos parte del grupo definido como group owner y en otros se nos apliquen los permisos de la entidad others

Bits de permiso

Los sistemas GNU/Linux utilizan 3 bits de permiso para codificar las diferentes políticas de seguridad sobre los recursos del sistema. Estos 3 bits de permiso son los de lectura ( r ), escritura ( w ) y ejecución ( x ), y se encuentran representados con estas letras y en este orden de aparición.

Permiso de lectura

El permiso de lectura, identificado con la letra r , nos da acceso de lectura a los recursos del sistema. En este sentido debemos diferenciar entre ficheros y directorios para entender como se aplica en cada caso:

  • Ficheros: el permiso de lectura nos permite poder visualizar el contenido de un fichero, leerlo
  • Directorios: el permiso de lectura nos permite consultar el nombre del contenido del directorio, es decir de los ficheros y directorios que se encuentren en su interior

Permiso de escritura

El permiso de escritura, identificado con la letra w , nos da acceso de escriutra (o modifiación) sobre los recursos del sistema. En este sentido debemos diferenciar también entre ficheros y directorios para entender como se aplica en cada caso:

  • Fichero: el permiso de escritura nos permite editar (o eliminar) un fichero
  • Directorio: el permiso de escritura nos permite poder guardar recursos (ficheros o directorios) dentro de él

Permiso de ejecución

El permiso de ejecución, identificado con la letra x , nos permite ejecutar recursos del sistema. En este caso también hay que diferenciar entre ficheros y directorios para entender su funcionamiento:

  • Fichero: el permiso de ejecución nos permite ejecutar un fichero, por lo que sólo tiene sentido en ficheros ejecutables, como pueden ser comandos o scripts de shell. El resto de ficheros del sistema no necesitan este permiso ya que no son ejecutados, sino que son consultados (para leer o modificara )
  • Directorio: el permiso de ejecución nos permite poder acceder a un directorio. Es importante ver la diferencia entre poder consultar el contenido (permiso de lectura) y el de poder estar dentro del directorio (permiso de ejecución)

Gestión de permisos

La gestión de permisos en un recurso del sistema (fichero o directorio), es decir, su modo , se realiza con el comando chmod ( change mode ). A través de este comando podemos establecer la configuración de permisos de un recurso, y para ello tenemos 2 formas de hacerlo.

Notación octal

Una representación muy habitual del modo de un recurso es la notación octal. Aprovechando el hecho de tener 3 bits de permiso con una posición definida cada uno de ellos nos permite representarlos con un código octal. De esta manera, cada entidad disppone de un código octal que define su configuración de permisos, por lo que la suma de los 3 conforma el modo del recurso.

Al igual que los permisos tienes una posición definida en su representación (de izqierda a derecha: lectura, excritura y ejecución) la identificación de las entidades también. La primera codificación de permisos representa al owner , la segunda al group owner y la tercera a others .

Por lo tanto, siguiendo todo lo expuesto y fijándonos en la siguiente tabla, podemos concluir que un recurso con el modo "rwx r-x r--" se corresponde con el código "754"

Permisos del fichero Codificación binaria Codificación octal
--- 000 0
--x 001 1
-w- 010 2
-wx 011 3

Notación simbólica

Otra forma de poder gestionar los permisos de un recurso es con la notación simbólica. En este caso vamos a identificar a cada entidad y permiso con una letra, así como a las operaciones que queremos realizar (añadir, quitar o definir permisos). En la sigueinte tabla observamos todas las codificaciones disponibles

Entidad Operación Bit de permiso
Owner --> u Añadir --> + Lectura --> r
Group Owner --> g Quitar --> - Escritura --> w
Others --> o Definir --> = Ejecución --> x

De esta manera, si queremos quitar el permiso de ejecución a la entidad group owner haríamos un chmod g-x file o si queremos añadir permiso de lectura a la entidad others haríamos chmod o+r file

Con este tipo de notación vamos a poder gestionar los permisos entidad por entidad, o de varias entidades a la vez si comparten modo , pero no vamos a poder aplicar (en una sola instrucción) una política de permisos diferente para caa una de las entidades.
